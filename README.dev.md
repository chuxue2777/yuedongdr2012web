# 乐动达人 2013 · 网页版

用 **2013 版 IPA 里的原始资源**（图集、谱面、音乐）+ 一套 cocos2d 语义的 JS 运行时，
在浏览器里跑起来的可演奏版本。

- 启动：双击 `index.html`（`file://` 直接可跑，不需要起服务器）
- 需要服务器时：`python -m http.server 8130`，访问 `http://127.0.0.1:8130/index.html`

---

## 一、先说清楚「重新用 cocos2d 编译成网页」这件事

这条路径**做不到**，不是实现问题，是素材链断在源头：

| 需要的东西 | 现状 |
|---|---|
| `*.xcodeproj` + `Classes/*.cpp` 源码 | 两个 IPA 里 **0 个**（`find` 已验证） |
| cocos2d-x 1.0.x 的 Web 后端 | **不存在**。Emscripten 支持是 3.x 才有 |
| cocos2d-html5 | 是**另写一套 JS 引擎**，不是 C++ 编译器 |

所以「原封不动拿去编译」没有输入。逆向能还原的是**结构、常量、调用图**，不是作者原来的
变量名和注释——产出的只能是"等价源码"，不是原文件。

这里走的是同样目标下唯一可行的那条：**资源不重画、谱面不重编、手感不重调**，
只把引擎层用 JS 按 cocos2d 的 API 形状重做一遍。将来若 `.xcodeproj` 出现，
`js/scene_game.js` 里的逻辑可以按函数逐个翻回 C++（API 名故意对齐 `cc.Sprite` /
`setPosition` / `setAnchorPoint` / `runScene`）。

## 三、演奏页背景层：原版 Lua 原封不动跑起来

这是「完全还原」最关键的一块，也是唯一真正做到"零改写"的部分。

各曲包的 `1200XX.zip` 里带一份 `config.lua`（9~17 KB），**是没编译的原始 Lua 源码**，
不是字节码。里面写着演奏页背景每个图层的贴图、坐标、锚点、动作、状态机和滚动逻辑。
8 份文件 md5 全不同 —— 每首歌的背景是各写各的：

| 曲包 | 主要用法 | 调度器 |
|---|---|---|
| 120001 | `move_tick` 双条纹理无缝上滚 | `move_tick@0.01` |
| 120002 | 最复杂，23 个节点，用到 `setFlipX` 镜像 | `move_tick@0.01` |
| 120003 | 纯动作链，无自定义 tick | — |
| 120004 | 8 个节点，最简 | — |
| 120005 | `shuaicong_tick` 自定义滚动 | `shuaicong_tick@0.01` |
| 120006 | 18 节点 + 9 组循环动作 | — |
| 120007 | 双条纹理上滚 | `move_tick@0.01` |
| 120008 | 用到**表构造 + `for` 循环**批量建图 | — |

做法不是照着抄成 JS（那就是重写），而是：

1. `js/lua.js` —— Lua 5.1 子集解释器（词法 → 递归下降/优先级爬升 → AST → 求值）。
   支持这 8 份文件实际用到的全部语法：`local` / `function` / `if-then-end` /
   `for i=a,b[,c]` / `while` / 表构造 / `..` / 算术比较逻辑运算 / 方法调用 `a:b()`。
   不做的：元表、协程、varargs、多返回值、goto（这 8 份文件一条都没用到，已逐项 grep 确认）。
2. `js/cocos2d_lua.js` —— cocos2d-iPhone 1.x 的 `CC*` 绑定（21 个类）+ node/action 语义。
   关键点：**cocos2d 锚点 y 向上**，`anchor(0,0)` 是左下角、`(0,1)` 是左上角；
   action 在 `runAction` 那一刻快照起始值；`CCRepeatForever` 每轮 `reset()`。
3. `cc.LuaBackLayer` 在演奏场景里 `XMLHttpRequest` 取 `config.lua` 原文直接执行，
   `InitBackLayer(filepath)` 走一遍就出背景。

**连击状态切换**：原生代码在连击到阈值时调 `backLayerCommonState()` /
`backlayerSpecialState()`，这两个函数名 8 份 lua 里全都有。阈值本身在 IPA 二进制里
（不在 lua 里），当前按火焰音符阈值 30 对齐 —— 这一项仍是**推定值**。

原作者留了个笔误没改：`backLayerCommonState()` 里写的是 `specialState = ture;`
（`ture` 而不是 `true`）。按 Lua 语义这等价于赋 `nil`，效果等于 false，恰好是想要的行为，
所以**原样保留，没动原文件一个字**。

### 验证方式

`test_lua.js` 是个不开浏览器的离线测试台，直接在 Node 里把 8 份 `config.lua` 全部喂进解释器：

```
node test_lua.js
OK   120001: 节点15 动作2 调度[move_tick@0.01]
OK   120002: 节点23 动作1 调度[move_tick@0.01]
...
OK   120008: 节点28 动作15 调度[]
全部通过
```

每份都会跑 InitBackLayer → 60 帧 → 切 special 30 帧 → 切 common 30 帧，
任何一帧抛错都算失败。

## 六、目录

```
web2013/
├─ index.html
├─ css/style.css
├─ js/
│   ├─ cc.js             cocos2d-x 风格微型运行时（Node/Sprite/Layer/Scene/Director/音频时钟）
│   ├─ lua.js            Lua 5.1 子集解释器（跑 config.lua 用）
│   ├─ cocos2d_lua.js    cocos2d-iPhone 1.x 的 CC* 绑定 + LuaBackLayer 宿主
│   ├─ atlas.js          14 张图集的帧表（原版 plist/XML 转出）
│   ├─ songs.js          8 曲 × 2 模式的完整谱面数据
│   ├─ scene_game.js     演奏场景：原版 Lua 背景层 / 透视轨道 / 判定 / 计分 / 长按 / 暂停
│   ├─ scenes_menu.js    标题 / 曲目列表 / 结算
│   └─ main.js           装配与预载
├─ test_lua.js           离线测试台：不开浏览器跑 8 份 config.lua
└─ assets/
    ├─ atlas/            14 张解码后的图集（CgBI → 标准 PNG）
    └─ songs/1200XX/     music.mp3 + config.lua + 全部背景/封面贴图
```

资源解码说明：2013 包里的 PNG 全是 Apple 的 **CgBI** 格式（额外 `CgBI` 块、
裸 deflate、BGRA 顺序、预乘 alpha），直接当 PNG 读会报 `broken data stream`。
本项目用 `_lddr2/cgbi.py` 批量还原成标准 PNG（281 成功 / 19 直通 / 5 张隔行图失败），
转换结果已放进 `assets/atlas/`，运行时不需要再转。

## 八、已知差距 / 下一步

1. **判定窗口不是原版数值**。`RULES` 里的 55/110/170ms 是同类音游的合理取值，
   不是逆向结论。要拿到真值得继续：把 11726 个函数的边界按 vtable 归到 12 个类，
   再反汇编 `GameScene` 的判定分支。
2. **连击状态切换阈值不是原版数值**。`config.lua` 里的 `backLayerCommonState` /
   `backlayerSpecialState` 是原生代码调的，调用点的连击数在二进制里，当前按 30 对齐。
3. **轨道是重建的**。2013 包里只有 `Ball` + `Tail`，没有轨道贴图；
   现在这套 3/4 线收敛透视是照 2011 版 `Line.png` 的关系画的。
4. **长按的尾巴判定偏宽松**（松手判 Miss，但不做长度插值）。
5. **没有做**：商城/广告/账号/排行榜/成就墙（原版这些依赖服务端，IPA 里没有逻辑）。
6. 2013 版 `base.xml` 里有 100+ 首曲目，包里只带 8 首；列表只显示这 8 首。
7. **结算/列表/标题场景没有原版 Lua 可跑**。IPA 里只有曲包自带的演奏背景层 `config.lua`，
   这三个场景的原版逻辑在 C++ 里，没有对应的 lua 文件。所以它们的版面是用原版图集
   + 反推规则实现的，属于「用原版素材重建」，不是「原版逻辑直接执行」。
